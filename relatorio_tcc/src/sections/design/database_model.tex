\subsection{Modelo de Banco de Dados}
\label{sec:modelo_bd}

A persistência de dados da plataforma é gerenciada por um banco de dados relacional, que foi projetado em duas etapas: um modelo lógico, que define as entidades e seus relacionamentos de forma agnóstica à tecnologia, e um modelo físico, que detalha a implementação específica no SGBD PostgreSQL.

\subsubsection{Modelo Lógico}

O modelo lógico foi concebido para refletir o domínio da aplicação, com a entidade \textbf{Mídia} atuando como o agregado central. As outras entidades principais, como \textbf{Transcrição} e \textbf{Resumo}, são tratadas como partes integrantes da Mídia, estabelecendo um relacionamento de composição.

\begin{itemize}
    \item \textbf{Usuário}: Representa um ator no sistema. Um usuário pode possuir (agregação) múltiplos itens de mídia.
        \begin{itemize}
            \item Atributos: ID, E-mail, Hash da Senha, Papel (Role).
        \end{itemize}

    \item \textbf{Mídia}: A entidade central que representa qualquer arquivo de conteúdo enviado pelo usuário. É a raiz do agregado de processamento.
        \begin{itemize}
            \item Atributos: ID, ID do Usuário, Caminho do Arquivo Original, Tipo da Mídia, Status do Processamento, Provedor de Armazenamento, Mensagem de Erro.
        \end{itemize}

    \item \textbf{Transcrição}: Representa o artefato textual gerado a partir de uma mídia de áudio. Existe como uma parte da Mídia (composição).
        \begin{itemize}
            \item Atributos: ID, ID da Mídia, Texto, Provedor, Status.
        \end{itemize}

    \item \textbf{Resumo}: Representa o artefato de resumo gerado a partir de um conteúdo textual. Também existe como uma parte da Mídia (composição).
        \begin{itemize}
            \item Atributos: ID, ID da Mídia, Texto, Provedor, Status.
        \end{itemize}
\end{itemize}

O relacionamento chave neste modelo é que tanto \textbf{Transcrição} quanto \textbf{Resumo} se relacionam diretamente com \textbf{Mídia}. Isso desacopla os artefatos do pipeline, permitindo, por exemplo, que um resumo seja gerado para uma mídia do tipo TEXTO que nunca teve uma transcrição.

\subsubsection{Modelo Físico (PostgreSQL)}

O modelo físico traduz o design lógico para uma implementação concreta no PostgreSQL, definindo os tipos de dados, chaves e restrições. A seguir, são detalhadas as principais tabelas do esquema.

\begin{description}
    \item[Tabela \texttt{users}] Armazena os dados dos usuários.
        \begin{itemize}
            \item \texttt{id}: \texttt{UUID}, Chave Primária.
            \item \texttt{email}: \texttt{VARCHAR}, Restrição Única (Unique Constraint).
            \item \texttt{password\_hash}: \texttt{VARCHAR}.
            \item \texttt{role}: \texttt{ENUM}('USER', 'ADMIN').
        \end{itemize}

    \item[Tabela \texttt{media}] A tabela central do sistema.
        \begin{itemize}
            \item \texttt{id}: \texttt{UUID}, Chave Primária.
            \item \texttt{user\_id}: \texttt{UUID}, Chave Estrangeira para \texttt{users.id}.
            \item \texttt{original\_file\_path}: \texttt{VARCHAR}.
            \item \texttt{media\_type}: \texttt{ENUM}('VIDEO', 'AUDIO', 'TEXT').
            \item \texttt{status}: \texttt{ENUM}('UPLOADED', 'PROCESSING', 'COMPLETED', 'FAILED').
            \item \texttt{storage\_provider}: \texttt{VARCHAR}.
            \item \texttt{error\_message}: \texttt{VARCHAR}, Nulável.
        \end{itemize}

    \item[Tabela \texttt{transcriptions}] Armazena os resultados da transcrição.
        \begin{itemize}
            \item \texttt{id}: \texttt{UUID}, Chave Primária.
            \item \texttt{media\_id}: \texttt{UUID}, Chave Estrangeira para \texttt{media.id}, com Restrição Única para garantir um relacionamento um-para-um.
            \item \texttt{text}: \texttt{TEXT}.
            \item \texttt{provider}: \texttt{VARCHAR}.
            \item \texttt{status}: \texttt{ENUM}('PROCESSING', 'COMPLETED', 'FAILED').
        \end{itemize}

    \item[Tabela \texttt{summaries}] Armazena os resultados da sumarização.
        \begin{itemize}
            \item \texttt{id}: \texttt{UUID}, Chave Primária.
            \item \texttt{media\_id}: \texttt{UUID}, Chave Estrangeira para \texttt{media.id}, com Restrição Única.
            \item \texttt{text}: \texttt{TEXT}.
            \item \texttt{provider}: \texttt{VARCHAR}.
            \item \texttt{status}: \texttt{ENUM}('PENDING', 'PROCESSING', 'COMPLETED', 'FAILED').
        \end{itemize}
\end{description}

A implementação física utiliza \texttt{UUID} como chaves primárias para garantir identificadores únicos em um sistema distribuído e \texttt{ENUM} para os campos de status e tipo, o que otimiza o armazenamento e garante a integridade dos dados. A gestão e a evolução deste esquema são realizadas através da ferramenta de migração de banco de dados Alembic.

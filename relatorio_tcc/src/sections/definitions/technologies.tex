\subsection{Tecnologias Utilizadas}
\label{sec:tecnologias}

A seleção das tecnologias para este projeto foi guiada pelos requisitos não funcionais de performance, escalabilidade, manutenibilidade e extensibilidade. A seguir, são detalhadas as principais ferramentas e bibliotecas utilizadas, juntamente com a justificativa para sua escolha.

\begin{description}
    \item[Python 3.11] A linguagem de programação principal foi escolhida devido ao seu robusto ecossistema de bibliotecas para ciência de dados, inteligência artificial e desenvolvimento web, além de seu forte suporte a programação assíncrona, que é um pilar desta arquitetura.

    \item[FastAPI] Como framework web, o FastAPI foi selecionado por sua alta performance, comparável a NodeJS e Go, e por seu suporte nativo a operações assíncronas com \texttt{async/await}. Sua integração com Pydantic para validação de dados e a geração automática de documentação interativa no padrão OpenAPI (Swagger) foram fatores decisivos para garantir a qualidade e a usabilidade da API.

    \item[PostgreSQL e SQLAlchemy] Para a persistência de dados, foi escolhido o PostgreSQL, um sistema de gerenciamento de banco de dados objeto-relacional conhecido por sua robustez, confiabilidade e suporte a tipos de dados avançados. A interação com o banco de dados é gerenciada pelo \textbf{SQLAlchemy}, um ORM (Object-Relational Mapper) que fornece uma poderosa abstração sobre o SQL e possui excelente suporte a operações assíncronas através do driver \texttt{asyncpg}.

    \item[Celery e Redis] Para atender ao requisito de responsividade da API, todas as tarefas de processamento de longa duração são executadas de forma assíncrona. O \textbf{Celery} foi escolhido como o gerenciador de filas de tarefas distribuídas, por ser o padrão da indústria no ecossistema Python. O \textbf{Redis} foi utilizado como o \textit{message broker}, devido à sua alta performance e baixa latência, garantindo a comunicação eficiente entre a API e os workers Celery.

    \item[OpenAI Whisper e Hugging Face Transformers] Para as funcionalidades de IA, foram escolhidas bibliotecas de código aberto e estado da arte. O \textbf{Whisper} da OpenAI foi utilizado para o reconhecimento de fala, devido à sua alta acurácia em múltiplos idiomas. A biblioteca \textbf{Transformers} da Hugging Face foi utilizada para a sumarização abstrativa, por fornecer acesso fácil a uma vasta gama de modelos pré-treinados (como T5 e BART).

    \item[PyMuPDF (fitz)] Para a extração de texto de documentos PDF, foi escolhida a biblioteca PyMuPDF, conhecida por sua alta performance e precisão na extração de conteúdo textual, permitindo que o pipeline de sumarização seja estendido para documentos estáticos.

    \item[Docker e Docker Compose] A containerização com Docker foi adotada para criar ambientes de desenvolvimento, teste e produção que são portáteis, consistentes e isolados. O \textbf{Docker Compose} é utilizado para orquestrar todos os serviços da aplicação (API, worker, banco de dados, Redis, etc.), simplificando drasticamente a configuração e a execução do sistema em qualquer máquina.

    \item[OpenTelemetry, Jaeger e Prometheus] Para garantir a observabilidade de um sistema distribuído e assíncrono, foi implementada uma estratégia completa baseada em padrões da indústria. O \textbf{OpenTelemetry} é utilizado para a instrumentação e a geração de traces distribuídos, o \textbf{Jaeger} para a visualização e análise desses traces, e o \textbf{Prometheus} para a coleta e o monitoramento de métricas de aplicação e negócio.

\end{description}

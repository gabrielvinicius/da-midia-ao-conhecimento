# Fase 1 – Baseline de Arquitetura e Código (03/11/2025)

Este documento captura o estado atual do branch `refactor/admin-facade` (commit `49081157b816c8a709fffe1207768cecede37e67`) para alimentar a Fase 1 do plano de refatoração Stage6.

## 1. Rotas e Módulos Ativos
- `main.py` agora importa apenas o router consolidado `src/text_analysis/api/routers`; os diretórios de sumarização, sentimento e tópicos foram limpos dos routers legados, restando apenas os serviços e repositórios utilizados pelo novo fluxo. Os testes criam stubs mínimos para notificações (`src/notifications/config/settings.py`, adapters) a fim de permitir a importação do módulo completo durante a suíte.
- Os submódulos de texto recebem o `TextAnalysisService` centralizado via bootstrap e retornam ACKs (`task_id`) ao agendar processamento assíncrono; os fluxos `POST /summaries/reprocess`, `POST /sentiment-analysis/*` e `POST /topic-modeling/*` já respondem nesse formato e os endpoints de leitura foram migrados para a nova camada.
- Diretórios legados remanescentes fora de `text_analysis` continuam: `src/media_processing/transcription/`, `src/media_processing/video_processing/`, `src/video_management/`.
- `src/admin/application/admin_service.py:31-118` mantém lógica condicional (`enabled`) que redireciona chamadas para serviços antigos ao invés de usar apenas adapters.

## 2. EventBus + Celery
- `register_domain_event_handlers` já associa `MediaUploaded`, `TextContentReady` e `NotificationRequested` a handlers reais, porém a lógica de domínio ainda reside dentro das tasks Celery.
- Tarefas Celery concentram lógica de domínio (ex.: `src/media_processing/tasks.py:40-158`, `src/text_analysis/tasks.py:38-162`), destoando da arquitetura de fachada que deveria publicar eventos e delegar somente execução pesada.
- Celery é inicializado via `src/celery_app.py`; permanecem pendentes validações de instância única conforme boas práticas (Context7 `/celery/celery`).

## 3. Bootstrap e Dependências
- `StorageServiceFactory` já é importado corretamente em `main.py`, eliminando o `NameError` registrado anteriormente.

## 6. Riscos Imediatos
- **Arquitetura inconsistente:** coexistência de módulos legados e consolidado impede remoção definitiva dos adapters antigos.
- **Orquestração híbrida incompleta:** tasks Celery continuam com regras de negócio e o EventBus ainda não dispara fluxos totalmente desacoplados.
- **Sem garantias de teste:** suíte pytest indisponível; pipelines podem falhar.

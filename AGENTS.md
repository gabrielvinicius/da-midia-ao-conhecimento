# Repository Guidelines

## Project Structure & Module Organization
Backend code lives in `src/`, grouped by bounded contexts such as `media_management`, `media_processing`, `text_analysis`, `storage`, and `admin`. The system operates as a **Modular Monolith** with **Clean Architecture** and **DDD**.

- `media_processing`: Orchestrates the Multimodal pipeline (Whisper for audio; for vision, the Ollama multimodal model by default, Moondream 2 as an option). Celery tasks are in the module-root `tasks.py`.
- `text_analysis`: Granular pipeline (Chunking -> Embeddings -> Sentiment -> Topics -> Indexing -> Topic titles -> Content genre -> Summary -> Chapters -> Review questions -> Grounding check). Synthesis via Ollama (Qwen3.5-9B, Gemma 4 as reserve), guided by the content genre. Chapter cuts come from the topic runs (the LLM only titles them); review questions point to a chapter, converted to its time. Frame descriptions arrive ready from `media_processing`. Search reranks the vector candidates with a cross-encoder (`RerankerPort`, `SEARCH_RERANKER_MODEL`).
- `storage`: High-level ports for swappable backends (Local/S3; the `s3` Compose profile runs Garage locally). Includes `StorageMaintenanceService` for cleanup.
- `shared`: Common domain events, infrastructure middleware, and the `pgvector` semantic indexing bridge.

### Core Architectural Mandates
- **Pure Dependency Injection**: All dependencies MUST be composed in `main.py` via `bootstrap.py` factories. Avoid global singletons. The only process-wide state allowed is explicit and centralized: loaded AI models in `shared/infrastructure/model_cache.py` and the worker's event bus in `shared/infrastructure/messaging/process_bus.py`.
- **Shared kernel**: application and domain code may import only `shared.domain` and `shared.application` (ports such as `LoggerPort`, `SupportsEventBus`, `UnitOfWorkPort`, `UserRole`), never `shared.infrastructure`.
- **Data ownership**: a module queries only its own tables (enforced by `tests/unit/test_architecture_table_ownership.py`); to know about another module's data, define a port and let that module implement it.
- **Integration events**: each event in `shared/domain/events.py` declares `published_by`; only that module creates it (`tests/unit/test_architecture_event_ownership.py`).
- **Event payloads**: events carry typed fields only, never a free `metadata` dict (checked by the same test). IDs travel as strings and become UUIDs on entry through `shared/domain/value_objects/identifiers.py` (`parse_id`, `parse_media_id`).
- **Queues**: Celery task and queue names live in `shared/events/integration_events.py`; the `-Q` lists in the docker-compose files must match (`tests/unit/test_queue_names.py`).
- **Transactions**: a repository commits its own single-aggregate change; a use case that touches several repositories runs inside `UnitOfWorkPort.transaction()` (repositories then only flush).
- **Single composition**: each application service has one factory, in its module's `infrastructure/dependencies/builders.py`, used by the API bootstrap, the workers and the event handlers alike. API dependency defaults (`api/dependencies.py`) never build services; they raise until `bootstrap.bind_*_module` binds the instance (`tests/unit/test_architecture_single_composition.py`).
- **Errors**: application and domain errors extend `shared/domain/errors.py` (`NotFoundError`, `AccessDeniedError`, `ConflictError`, `TemporarilyUnavailableError`, `ValidationError`, `DomainError`). They are translated to HTTP in one place (`shared/infrastructure/exceptions/exception_handlers.py`); routes don't catch them just to change the status code. Unexpected errors become a 500 without the internal message.
- **Complexity**: functions stay at McCabe complexity 12 or less (checked in CI); split long flows into named steps.
- **Data model**: ids are UUID; timestamps are `DateTime(timezone=True)` in UTC (`shared/domain/time/clock.utcnow`); enums are stored as text via `shared/infrastructure/database/types.enum_column` (no native PostgreSQL enums). Tables derived from a media reference `media.id` with a foreign key; deletion is done by the application (`MediaDataEraserPort` per media, `UserDataEraserPort` per user), never by cascades across modules.
- **Repositories**: map rows to domain objects right away; no `rollback` before reads (a failed commit is rolled back inside `unit_of_work.commit`); no `refresh` after commit unless a server-side default must be read.
- **Rich entities**: state changes go through entity methods (`mark_as_failed`, `mark_as_processing`, `mark_as_extracted`), never by assigning `status` from services.
- **Observability**: logs are JSON by default (`LOG_FORMAT=console` for local reading) and every line carries the `correlation_id` bound in `contextvars` by `CorrelationIdMiddleware` (API) or `task_prerun` (Celery). The request id travels in `MediaUploaded` to the queued tasks. Prometheus metrics are never served by the public API: API and workers expose them on the internal `METRICS_PORT` (workers in multiprocess mode, `PROMETHEUS_MULTIPROC_DIR`), scraped by the `prometheus` Compose service. `/health` checks the database and Redis and answers 503 when one is down.
- **Analysis factors**: sentiment, topics (with titles), grounding, chapters and questions are optional (`ANALYSIS_FACTORS`); frame description is switched off with `VISUAL_PROVIDER=none`. A switched-off factor is left out of the pipeline and its model is never loaded; later steps must cope with its absence. Chunking, chunk embeddings, indexing, content genre and synthesis always run.
- **No silent substitutes**: an adapter whose model did not load raises (`TemporarilyUnavailableError`) instead of returning made-up output. Hash vectors made the search return random excerpts and keyword rules replaced the sentiment model without anyone noticing; a failing optional step is recorded as failed, a failing required one fails the analysis.
- **Media lifecycle**: `uploaded → processing → analyzing → completed`, any stage → `failed`, `failed → processing` (reprocess). Transitions live in `Media` (and `Transcription`); an out-of-order event is refused by the entity and ignored by `MediaLifecycle`. The media is `completed` only on `AnalysisCompleted`; `AnalysisFailed` fails it. Media stuck in `analyzing` are failed by `UnfinishedAnalysisRecovery`. A finished transcription is never re-run (`Transcription.is_finished`); a recording without speech fails at once (`NoSpeechFoundError`).
- **End of the pipeline**: text_analysis publishes `AnalysisCompleted` (topic titles, overall tone, failed steps, summary source) and `AnalysisFailed`; new layers subscribe to them. Media state subscribes in `media_management/worker.py`; notifications subscribe to the pipeline events in `notifications/worker.py` (both bound by `src/worker_process.py`); media_processing and text_analysis never import notifications (`.importlinter`). A subscriber failure must not reach the publisher (it would re-run GPU work).
- **Task retries** (`shared/infrastructure/tasks/retry.py`, at most `PIPELINE_MAX_RETRIES`): transcription and text extraction retry everything except permanent errors (`shared.domain.errors.is_permanent_failure`: any `DomainError` but `TemporarilyUnavailableError`) via `retry_unless_permanent`; the analysis retries only transient errors. A permanent error is final on the first attempt. One analysis per media (unique `media_id`): a retry overwrites the previous one.
- **Workers**: `src/celery_app.py` holds only configuration (the API imports it to send tasks); the worker process assembly is `src/worker_process.py` (loaded by name through `include`), which lists every module's subscriptions in order (media state, processing, notices last). The process bus subscribes them when created, so a failure reaches the task instead of being swallowed by a Celery signal (`.importlinter` forbids `celery_app` and `shared` from importing it). Results are not stored (`task_ignore_result`). GPU tasks have a hard `time_limit` (processing maximum); the analysis has a soft limit that announces `AnalysisFailed`, below `MEDIA_ANALYSIS_GIVE_UP_MINUTES`. A task delivered again after finishing re-announces the stored result (unless a reprocess replaced it) instead of doing nothing. Task bodies run with `asyncio.run`.
- **Media files**: workers stage the media on disk with `StoragePort.download_to`, never `retrieve` into memory; transcription, frame description and text extraction share `processing_job.staged_file`.
- **Analysis state**: language, visual context, summary source (`SummarySource`), grounding report and step outcomes are typed fields of `Analysis`; `diagnostics` holds only technical details. `application/mappers.analysis_diagnostics`/`restore_from_diagnostics` keep the stored and API `diagnostics` format.
- **Storage paths**: `FilePath` accepts only relative paths without `..`; every adapter relies on it.
- **Time**: domain and application read the clock only through `shared/domain/time/clock.utcnow`; recording times are formatted by `shared/domain/time/timestamps.format_timestamp`.
- **Authentication**: every token is checked by `AuthService.user_for_token(token, purpose, resource)`. Access tokens go only in the `Authorization` header; the video URL and the WebSocket use short scoped tokens (`POST /auth/scoped-token`, `application/tokens.TokenPurpose`). Refresh tokens rotate on use and are revoked on logout (`RevokedTokensPort`, Redis).
- **API never runs analysis models**: analysis requests from the API go to the queue (`AnalysisRequestService`); the API composes only read, review, request and search services of text_analysis. Search runs two light models on the API's CPU (query embedding and reranker); the API container has no GPU (`AI_DEVICE: cpu`).
- **Access rule**: owner or admin, 404 for everyone else, in one place (`shared/application/access.py`: `Requester`, `ensure_can_access`), applied by the services of media, transcriptions, analyses and notices; routes get the `Requester` from `user_management.api.dependencies.get_requester` and never check ownership themselves.
- **API responses**: typed schemas; lists use `shared/api/schemas.PaginatedResponse`.
- **Logs**: no personal data (e-mails masked with `shared/application/privacy.masked_email`, search text never logged); Prometheus labels never carry media or user ids.
- **Text generation**: only through Ollama (`OllamaTextGenerationAdapter`, main and reserve model from settings). There is no Transformers path for the LLM.
- **Deployment**: `docker-compose.yml` is production (no host code mounts; every app service gets `env_file: .env` plus the shared `x-app-environment`, `APP_ENV=production`, `restart: unless-stopped`, log rotation with the `local` driver, `no-new-privileges` and, for our own non-root images, `cap_drop: [ALL]`; every image has a fixed version or digest and no service has `container_name`, checked by `tests/unit/test_deployment_config.py`); optional services are Compose profiles enabled by `COMPOSE_PROFILES` in `.env` (`internet`: Cloudflare Tunnel; `s3`: Garage single node, `docker/garage.toml`, creating the key and bucket from `STORAGE_S3_*` at start; needs `GARAGE_RPC_SECRET`; ADR-019); migrations run in the one-shot `migrate` service, which the API and workers wait for (`service_completed_successfully`); workers have a Celery ping healthcheck; variants only override what differs (`docker-compose.cpu.yml`, `docker-compose.rocm.yml`); host code mounts live in `docker-compose.dev.yml`. Data volumes must target the image's data directory (Postgres 17: `/var/lib/postgresql/data`, with `PGDATA` in its `pgdata` subfolder; Redis with AOF: `/data`); model caches go to `/app/.cache` (`XDG_CACHE_HOME`). Uploaded media live in `/app/storage`: the `media_data` volume, or a host folder when `MEDIA_STORAGE_PATH` is set (owned by uid 999; the backup scripts follow the same choice). Every variable in `.env.example` must be read by some setting (`tests/unit/test_deployment_config.py`). Backups: restic repository (`BACKUP_REPOSITORY`, `BACKUP_PASSWORD`) written by `scripts/ops/backup.sh` (database with `pg_dump -Fc`, media incremental, the Garage volume with its own metadata snapshot when it exists, retention, `restic check`), restored by `restore.sh` and tested by `verify-backup.sh` (restores the dump into a throwaway PostgreSQL); `.github/workflows/backup.yml` runs them daily (restore test on Sundays) on the production runner. Continuous deployment: `.github/workflows/deploy.yml` runs on the self-hosted runner labeled `producao` after CI passes on a push to `main`, checks out that commit in the production folder (repository variable `DEPLOY_DIR`, a separate clone with its own `.env`; the public address is `PUBLIC_URL`) and runs `scripts/ops/deploy.ps1`: images are tagged with the commit (`app:<commit>`, `frontend:<commit>`; Compose uses `${APP_TAG:-current}`), the healthy version is also tagged `current`, a failed health check brings back the previous commit's images without rebuilding, and only the last three versions plus a week of build cache are kept. The runner runs in the user session (Docker Desktop needs it), kept alive by the task from `scripts/ops/install-runner-task.ps1`, which also opens Docker Desktop before the runner (it does not start at logon by itself; after a power loss on 2026-10-15 the system stayed down until someone opened it). The Compose project name is declared once, in `name:` at the top of `docker-compose.yml`; volume names derive from it and the ops scripts read it from there (never `-p` or a repeated name; `tests/unit/test_deployment_config.py`). The platform name for the backend is `shared/domain/brand.PLATFORM_NAME` (the interface has `frontend/src/components/Brand.tsx`).
- **Dependencies**: runtime in `requirements.txt` with tested versions pinned by `~=` (GPU-only packages capped below the next major; `torch` and `torchvision` fixed and matched (2.14.1/0.29.1, CUDA 12.6 because CTranslate2 loads the CUDA 12 libraries), installed from the variant's index; `transformers` below 4.50 while Moondream 2 uses the 2024-08-26 revision); tests and linters in `requirements-dev.txt`, never in the image. Passwords use `bcrypt` directly and tokens use `PyJWT` (no passlib, no python-jose). Docker images use fixed tags, never `latest`.
- **Configuration**: environment-specific values (CORS origins in `CORS_ORIGINS`, hosts, models) come from settings, never hard-coded lists.
- **Hexagonal Integrity**: Business logic interacts with the world only through Ports (`application/ports.py`). Adapters stay in `infrastructure/`.
- **Granular Pipeline**: Analysis is step-based. Partial results MUST be saved to allow resilience and adaptive retries.
- **Semantic indexing**: Every processed chunk is vectorized via `pgvector` for global semantic search.

### Module Deprecations & Cleanup Status
- `media_management`: each operation is a use-case class in `application/use_cases/` (`UploadMedia`, `ResumableUpload`, `DeleteMedia`, `ReprocessMedia`, `StreamMedia`, `MediaLifecycle`); `MediaService` is only a facade over them. The web interface always uploads in parts (`/media/uploads`, 32 MB each, staged by `UploadStagingPort`), because Cloudflare refuses requests above 100 MB; completion goes through `UploadMedia`.
- `monitoring`: only `HardwareAdvisor` and `gpu_stats` (admin panel).
- `admin`: the processing queue (`GET /admin/queue`, `AdminQueueService`) lists media in progress oldest first, with owner, time in the current stage and a "stuck" flag, plus the Celery queue lengths read from Redis (`QueueDepthPort`). Logging and metrics live in `shared/infrastructure/observability`.
- `tests`: Directories like `tests/unit/auth` are removed. Unit tests reside within context folders (e.g., `tests/unit/user_management`).

## Intelligence & Autonomy Features
- **Multimodal Vision**: keyframes are described in `media_processing`, right after transcription, through `VisualAnalysisPort` (`VISUAL_PROVIDER`: `ollama`, the same Qwen3.5 as the summary, by default; `moondream`; or `none`). Consecutive descriptions of the same scene are kept once (`domain.visual_sampling.is_same_scene`).
- **Human-in-the-loop (HITL)**: Supports rating and editing AI outputs. Updates to summaries must preserve versioning for future fine-tuning. Every correction keeps the AI version on its first edit: summary (`diagnostics.original_ai_summary`), topic titles (`Topic.original_title`), chapters and questions (`original_ai_chapters`, `original_ai_review_questions`; `Analysis.correct_study_aids`), and transcript passages (`original_text` in the segment; `Transcription.correct_segment` rebuilds the full text, so the next analysis uses the correction). A new analysis regenerates analysis fields only when they have not been reviewed (ADR-015); transcript corrections stay.
- **Downloads**: the media page builds the files in the browser from what the API already returns (`frontend/src/features/media/lib/exporters.ts`): summary and study guide (Markdown), transcript (text with times, SRT, WebVTT), everything (JSON), and print/PDF. The stored summary keeps its appendix after `APPENDIX_MARKER`; the page shows and exports only the body.
- **Hardware Awareness**: `HardwareAdvisor` reports GPU/RAM pressure (whole-GPU readings via `nvidia-smi`) for the admin panel and processing deadlines.
- **JSONB Upcasting**: Persistence uses JSONB for metadata to support zero-downtime schema evolution.

## Analysis reliability (ADR-015)
- New analysis requests must refuse reviewed summaries, topic titles, chapters and questions with 409. The worker checks the same rule; generated persistence rechecks it under a row lock. Full reprocessing of failed media retains its explicit cleanup policy.
- Pipeline checkpoints use `save_generated`; persistence failures must reach the task retry policy. Checkpoints preserve partial output, but retries still execute every step.
- Persist `pipeline_completed` only after the pipeline finishes. Media recovery queries completed results through `AnalysisCompletionRecordsPort` before declaring a stalled analysis failed; never query another module's tables directly. Reconciliation runs at the configured analysis deadline and does not guarantee notification delivery.
- Queue identifiers and read text, segments, language and visual context from the same persisted source. Legacy embedded text must not override that source; requests for a replaced transcription are ignored.
- Failed model initialization must remain retryable. Synchronize concurrent embedding model loading.

## Build, Test, and Development Commands
- **Environment**: `pip install -r requirements.txt -r requirements-dev.txt` (torch and torchvision from the variant's PyTorch index, as in `ci.yml`). There is no Poetry.
- **Backend**: `uvicorn main:app --reload`, or the whole stack with `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build`.
- **Migrations**: `alembic upgrade head` (in Compose, the backend applies them at start).
- **Tests**: `pytest tests/unit tests/smoke tests/integration` (`TEST_POSTGRES_URL` for the PostgreSQL ones) and `E2E=1 pytest tests/e2e` against PostgreSQL and Redis.
- **Linting**: `ruff check src tests main.py` (CI selects runtime errors, dead code and McCabe ≤ 12).
- **Infrastructure checks** (CI job `deployment`): `docker compose config` for every variant, hadolint (`.hadolint.yaml`), actionlint (`.github/actionlint.yaml`) and zizmor on the workflows. Actions are pinned to a commit SHA with the version in a comment; Dependabot (`.github/dependabot.yml`) updates them. Images are built and scanned by Trivy in `images.yml`.
- **Architecture**: `lint-imports` checks the layer and module rules in `.importlinter` (also in CI). Composition code (`bootstrap.py`, `tasks.py`, `worker*.py`) lives at the module root, never in `application/`.

## Coding Style & Naming Conventions
- **Python**: 4-space indent, Ruff formatting, strict type hints.
- **Layering**: Stick to `Domain` -> `Application` -> `Infrastructure`.
- **TypeScript**: React 19 with TanStack Query, Tailwind 4 (theme in `src/index.css`, no `tailwind.config.js`), Vite 8. Use PascalCase for components. Lint includes the React Compiler rules (`eslint-plugin-react-hooks` 7): derive values during render or adjust state while rendering instead of `setState` in an effect, and keep `setState` updater functions pure (React 19 may run them later). A dialog opened from a menu item uses the item as its trigger (`DropdownMenuItem asChild` > `DialogTrigger asChild`), so focus moves into the dialog.

## Testing Guidelines
- Unit tests MUST use mocks for all external dependencies (Repositories, EventBus).
- Integration tests verify Port/Adapter connectivity.
- E2E tests (`tests/e2e`) validate the entire Multimodal flow from upload to summary correction.

## Commit & Pull Request Guidelines
- **Conventional Commits**: `feat(vision): ...`, `fix(vector): ...`.
- **PRs**: Must include validation logs and confirm that architectural purity (DI/Hexagonal) is maintained.
